## 2. データ取得の仕様

### ユーザー操作による取得タイミング
**ユーザーが「この求人を保存」ボタンをクリックした時のみ**データを取得します。

- 自動取得: **なし**
- バックグラウンド送信: **なし**
- ページ読み込み時の自動実行: **なし**

### 取得するデータ項目
1. **URL**: `window.location.href`（ページの完全URL）
2. **タイトル**: `document.title`（ページタイトル）
3. **コンテンツ**: ページのテキストコンテンツ（最大20,000文字）
   - HTMLタグは除去
   - スクリプト、スタイル、noscriptタグは除去
   - 見出しベースでセクション分割し、重要キーワードを含むセクションを優先抽出
4. **メタタグ**: **送信しない**（空配列）

**送信しないデータ**:
- HTML構造（`htmlStructure`）
- スクリーンショット
- クッキー
- ローカルストレージデータ
- フォーム入力値

### バックグラウンドでの自動送信
**存在しません**。すべてのデータ送信はユーザーの明示的な操作（ボタンクリック）によってのみ実行されます。

### ログイン必須ページへの対応
- ログイン必須ページでも動作しますが、**ログイン後のページ内容のみ**を取得します
- ログイン情報やセッション情報は取得しません
- ユーザーがログイン済みの状態でボタンをクリックした場合のみ、その時点のページ内容を取得します

## 3. 外部サービス連携

### Google Gemini API
- **利用目的**: 求人ページのテキストコンテンツから構造化データ（会社名、職種、年収、勤務地など）を抽出
- **送信データ範囲**: 
  - URL
  - タイトル
  - テキストコンテンツ（最大20,000文字、HTMLタグ除去済み）
  - **HTML構造は送信しない**
  - **メタタグは送信しない**
- **送信タイミング**: ユーザーがボタンをクリックした時のみ
- **データ保持**: Gemini APIへの送信データは学習に使用されないよう設定（Googleのサービス利用規約に従う）

### Firebase (Firestore)
- **保存データ項目**:
  - `userId`: ユーザーID（認証済みユーザーのID、または"anonymous"）
  - `url`: 求人ページのURL
  - `title`: ページタイトル
  - `content`: ページのテキストコンテンツ（最大20,000文字）
  - `createdAt`: 保存日時（サーバータイムスタンプ）
  - `sourceHost`: URLのホスト名
  - `isPinned`: ピン留めフラグ
  - `isArchived`: アーカイブフラグ
  - `pageType`: 求人ページ判定結果（`job_detail` / `job_list` / `non_job`）
  - `pageTypeScore`: 判定スコア（デバッグ用）
  - `isListPage`: 一覧ページフラグ
  - **抽出された構造化データ**:
    - `companyName`: 会社名
    - `jobTitle`: 職種名
    - `salaryMin`: 年収下限
    - `salaryMax`: 年収上限
    - `salaryBand`: 年収帯
    - `jobDescription`: 仕事内容
    - `requiredPerson`: 求める人物像
    - `jobType`: 職種カテゴリ
    - `industry`: 業種
    - `locationText`: 勤務地
    - `remoteType`: リモートワーク種別
    - `employmentType`: 雇用形態
    - `requiredYears`: 必要経験年数
    - `seniorityLevel`: シニアリティレベル

### 認証方式とトークンの保存方法
- **認証方式**: Firebase Authentication（メールアドレス + パスワード）
- **トークン保存場所**: `chrome.storage.local`（拡張機能のローカルストレージ）
- **トークン種類**: Firebase IDトークン（認証済みユーザーの場合）
- **未認証時の動作**: `userId: "anonymous"`として保存

### データの暗号化方式
- **通信**: HTTPS（TLS 1.2以上）
- **保存**: Firebase Firestore（Google Cloud Platformの暗号化）
- **パスワード**: Firebase Authenticationによる暗号化保存

## 8. 権限説明

### activeTab を使う理由
- **理由**: ユーザーが現在アクティブなタブでのみ動作するため
- **説明**: ユーザーが拡張機能のアイコンをクリックした時のみ、その時点で開いているタブの情報を取得します。他のタブやバックグラウンドタブにはアクセスしません。

### scripting を使う理由
- **理由**: ユーザー操作時にページ情報を取得するため
- **説明**: 「この求人を保存」ボタンをクリックした時のみ、`chrome.scripting.executeScript`を使用してページのURL、タイトル、テキストコンテンツを取得します。常時実行されるスクリプトではありません。

### storage を使う理由
- **理由**: 認証トークンをローカルに保存するため
- **説明**: ユーザーがWebアプリでログインした際の認証トークンを`chrome.storage.local`に保存し、APIリクエスト時に使用します。他のデータは保存しません。

### 最小権限になっているか
✅ **はい、最小権限です**
- `host_permissions`は使用していない（`<all_urls>`なし）
- `activeTab`のみで動作（現在のタブのみ）
- `scripting`はユーザー操作時のみ使用
- `storage`は認証トークンのみ保存

## 9. セキュリティ

### HTTPS のみか
- **API通信**: HTTPSのみ（`https://kyujin-bookmark.netlify.app/api/jobs/capture`）
- **Webアプリ**: HTTPSのみ
- **Firebase**: HTTPS通信
- **Gemini API**: HTTPS通信

### トークン保護
- **保存場所**: `chrome.storage.local`（拡張機能のローカルストレージ）
- **送信方法**: HTTPS通信で`Authorization`ヘッダーに含めて送信
- **有効期限**: Firebase IDトークンの有効期限に従う
- **漏洩対策**: トークンは暗号化されずに保存されるが、拡張機能のローカルストレージにのみ保存され、他の拡張機能やWebページからはアクセスできません

### ユーザー識別方法
- **認証済みユーザー**: Firebase AuthenticationのユーザーID（`request.auth.uid`）
- **未認証ユーザー**: `userId: "anonymous"`として保存
- **IPアドレス**: レート制限の識別に使用（ログには保存しない）

### 不正利用対策
- **レート制限**: 30件/分（一般リクエスト）、10件/分（Gemini API呼び出し）
- **認証**: Firebase Authenticationによるユーザー認証（オプション）
- **CORS制限**: 拡張機能IDに基づくCORS制限（本番環境）
- **Firestore Security Rules**: ユーザーごとのデータアクセス制御
