# LLM機能デバッグガイド

## 問題の可能性

### 1. APIキーが設定されていない
- **確認方法**: サーバーログで `[LLM] API_KEY存在確認: false` が表示される
- **対処**: `.env.local` または Netlify環境変数に `GEMINI_API_KEY` を設定

### 2. LLM処理が実行されていない
- **確認方法**: サーバーログで `[LLM] extractWithGemini 開始` が表示されない
- **対処**: API Routeのログを確認

### 3. LLM処理は実行されているが、結果が空または不正確
- **確認方法**: サーバーログで `[LLM] LLM抽出結果` を確認
- **原因の可能性**:
  - プロンプトが不適切
  - パースエラーが発生している
  - 元のテキストに情報が不足している

### 4. パースエラー
- **確認方法**: サーバーログで `❌ LLMレスポンスのパースエラー` が表示される
- **対処**: レスポンステキストを確認して、JSON形式を修正

## デバッグログの確認方法

### ローカル開発環境
```bash
npm run dev
```

サーバーログで以下を確認：
```
[LLM] extractWithGemini 開始
[LLM] API_KEY存在確認: true/false
[LLM] genAI存在確認: true/false
[LLM] プロンプト長: XXX 文字
[LLM] Gemini処理時間: XXXms
[LLM] レスポンステキスト（最初の500文字）: ...
[LLM] LLM抽出結果: {...}
```

### Netlify環境
- Netlifyダッシュボード → Functions → Logs で確認

## 修正内容

### ロジックベース抽出の完全削除
- **変更**: ロジックベース抽出を完全に削除し、LLMのみで抽出を実行
- **影響**: すべての抽出処理がLLMに依存するため、APIキーが必須
- **エラーハンドリング**: LLM処理が失敗した場合、空のデータを返すのではなくエラーをthrowします

## 次のステップ

1. サーバーログを確認して、どの段階で問題が発生しているか特定
2. LLM処理が実行されているか確認
3. LLMのレスポンスを確認
4. 結果が変わっているか確認
